# P16 — Controlled Operator Decision & Independent Closure Preparation

**Preparation only. Not a human acceptance, certified release, or deployment authorization.**

## Implementation and trust limits

- **Signed custody and revocation roster:** scripts/p16/custody.mjs verifies an Ed25519-signed roster against a root DER SHA-256 fingerprint supplied independently. It checks signer-key fingerprints, roles, revocations, source SHA, expiry and **rejects rollback below the independently retained minimum custody revision**. No production private keys or valid trust roots are shipped. The independent provenance of a supplied root fingerprint and the freshness of revocation data must be established by an external operator.
- **Authenticated hash-linked receipt format:** scripts/p16/receipt-history.mjs verifies numbered, SHA-256-linked P15 Ed25519 attestation receipts and a signed terminal checkpoint. It rejects tampered digests, stale source SHA, revoked keys, duplicate subjects and replayed UUIDv4 nonces. It requires a separately trusted prior sequence/digest. A self-supplied prior checkpoint is not a genuine trusted append-only history. The external operator must maintain an independently authenticated checkpoint ledger.
- **Physical device and operator evidence:** scripts/p16/operator.mjs correlates signed evidence digests and reviewer claims for Android Chrome, Samsung Internet, TalkBack and accessibility scenarios, and enforces the P15 no-op release rehearsal with same-original-origin and forward-only encrypted backup/recovery rules. Physical devices have NOT been tested; a matching JSON claim is not physical verification. It always reports releaseAuthorized=false and no release actions performed.
- **Read-only CLI:** scripts/p16/closure-cli.mjs reads only local evidence files and requires externally supplied MDD_CUSTODY_ROOT_SHA256, MDD_TRUSTED_LEDGER_DIGEST, MDD_TRUSTED_LEDGER_SEQUENCE and MDD_MIN_TRUSTED_CUSTODY_REVISION. These must come from an independently retained operator ledger, NOT from the input bundle. Run either:
  - node scripts/p16/closure-cli.mjs history BUNDLE_JSON EXACT_SHA CURRENT_ISO_TIME
  - node scripts/p16/closure-cli.mjs rehearse BUNDLE_JSON EXACT_SHA CURRENT_ISO_TIME
  - node --test scripts/p16/closure.check.mjs

Success of structural/signature verification exits **3**, rejected inputs exit **4**; there is no exit-zero release decision. Inputs and errors are never printed, and no network request, storage mutation, merge, deploy, cache purge or publication occurs. Testing keys are ephemeral and generated by local tests only.
