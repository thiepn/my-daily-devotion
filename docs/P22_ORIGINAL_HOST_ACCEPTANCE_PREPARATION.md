# P22 — Original-Host Acceptance Evidence & Independent Release Decision Isolation

**Status: preparation-only. NO_GO.** This phase creates an offline evidence-intake contract and does **not** authenticate real rights owners, operate phones, migrate user data, restore a backup, change credentials, merge, deploy or publish.

## Implementation

- `scripts/p22/source-custody.mjs` enforces exact source commit, original HTTPS origin/path and PWA scope, and **six bounded, source-specific evidence identities** for original objects, source rights, CDN rights, PWA manifest, service worker and offline cache. Every SHA-256 matches the P21 original-host evidence packet. Rights/CDN dispositions and all materials are **REVIEW_PENDING** or **REJECTED**, never self-approved. The complete payload is Ed25519-signed separately by a source custodian and independent rights reviewer with **distinct external public-key fingerprints and identities**, bounded validity, nonce anti-replay, and an externally retained previous sequence + digest. This validates integrity under supplied public keys; no keys, permissions or rights are granted, and no externally governed ledger is operated here.
- `scripts/p22/review.mjs` re-evaluates P21's two-stage signed owner NO_GO, and hence P20/P19/P18/P17 exact-archive, signer rotation and custody chains, **before** source escrow or device claims. Sparse, allowlisted original-host Android Chrome/Samsung Internet/TalkBack/keyboard/accessibility and migration packets must match existing exact-SHA signed receipt identifiers and evidence hashes, remain pending/rejected and include no personal device IDs, journal data or secret credentials. Absent real reviewer evidence remains explicitly unverified.
- `scripts/p22/review.mjs` previous-stable recovery escrow requires **a distinct previous-stable SHA and exact archive digest**, original unchanged host, installed database schema ≥3 with target ≥ installed schema, password-encrypted portable-v1 off-device backup evidence and a matching separately signed backup reviewer receipt. Only a disposable profile is permitted; deletion of original data, cache purge, schema downgrade and production journal writes are prohibited. This is evidence of a proposed recovery path, **not an actual prior-stable restore**.
- `scripts/p22/review-cli.mjs` accepts one local bounded JSON packet and a separate release ZIP. It requires independent P17/P19/P20/P21 witness/owner trust pins, replay ledgers and the additional `MDD_P22_EXTERNAL_ESCROW_PINS_JSON`, `MDD_P22_ESCROW_LEDGER_SEQUENCE`, `MDD_P22_ESCROW_LEDGER_DIGEST` and `MDD_P22_PREVIOUS_ESCROW_NONCES_JSON`. Trust anchors must originate in independently protected operator records, never the submitted packet. It emits **exit 3** for checked-but-unapproved data or **exit 4** for rejection; never exit 0 for permission. Errors are redacted; no network write or release operation.
- `scripts/p22/review.check.mjs` uses ephemeral fixture signers and real immutable ZIP bytes for 15 adversarial regression cases: changed origin/PWA, CDN/object/rights hashes, forged rights approval, duplicate source materials, signer identity/key conflict, expiry/replay, missing hardware receipts, unsafe previous-stable restoration, owner stage forgery, tampered ZIP and CLI privacy.
- Read-only scoped P22 GitHub CI, no deployment permissions. Mandatory release certification and unapproved screenshots are not modified.
