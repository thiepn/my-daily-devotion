# Focused Prayer journal

This release is stacked on `codex/morning-grace-v2-prayer-detail` / PR #18. It changes Focused Prayer and the shared context/focus primitives it needs. It does not redesign other workflows or merge/deploy the application.

## Session identity and actions

`/prayer/session?depth=quick|regular|extended&return=...` explicitly starts or resumes the existing deterministic queue. The route is replaced with `/prayer/session?session=<saved-id>&return=...`. Identified sessions preserve their date, depth and saved order across midnight, reloads and Detail/Scripture round trips. Invalid, missing, deleted and ended IDs never silently start a replacement session.

`PrayerSessionRepository.readState` is a readonly transaction. Reactive reads, foreground refreshes, context expansion and retries after entry use it. `loadState` is reserved for explicit entry/continuation and reconciles unavailable pending items in one transaction. Ended sessions are read without reconciliation.

Prayed, Skip, Answer and End return their committed state directly. Revision checks and pending-item checks run inside their transactions. A failed subsequent read cannot turn a successful action into a retry of that mutation. Prayed still updates the prayer, session item and existing `PRAYER_PRAYED` event atomically. Skip creates no prayed event. Answers retain the existing resolution/event behavior. Session prayed events keep the session date; answer dates retain existing action-date semantics.

Queue reasons are held only for the newly created view. They are never added to saved records or reconstructed from later metadata. Restored views use “Part of your saved session.” Library filters do not affect the queue.

## Writing and navigation

Answer notes remain memory-only until Mark answered succeeds. Merely opening, skipping, leaving or ending cannot record an answer. The shared journal dialog offers discard/keep-editing; unload warnings remain. Commit locks disable duplicate submissions and the answer field. If the request changes or disappears, existing writing remains copyable and requires explicit continuation. Changed revisions require review before answering.

Open prayer retains the canonical session URL as its return destination. The existing Detail → Settings chain remains intact. Scripture links keep full BSB ranges. The shared position helper preserves the originating control/scroll position, opens containing disclosures, and handles Back before a lazy route has finished loading. Route announcements do not override a more specific restored target.

## Presentation ownership

`src/styles/focused-prayer.css` owns the session composition in the `screens` layer. Seventy-four superseded session selectors were removed from seven legacy stylesheets. Shared tokens, journal surfaces, identity circles, dialogs, icons and the local olive sprig are reused. Mobile remains immersive; desktop retains the existing shell and a maximum 760px journal column.

See [visual review](visual/morning-grace-v2/focused-prayer-design-qa.md) for comparison evidence, corrected findings and limitations. No artwork generation or new asset license is needed.

## Compatibility and verification

Database schema remains **v1**. No stored fields, event types, backup format, Scripture identity, schedule rules, queue targets or service-worker rules changed. Durable drafts remain a later release.

Coverage includes readonly database snapshots, transaction rollback, duplicate and concurrent actions, midnight continuation/new-day starts, missing/deleted sources, frozen order, optional context failure/retry, stale loads, unsaved-answer protection and committed actions followed by failed refresh. Existing domain, queue, backup, offline and primary-screen image suites remain release gates.

The new deterministic image comparisons cover 320, 360, 390, 430, 768 and 1440px, dark mode, 200% text, long writing, expanded Scripture, answer editing, confirmation, prior-date resume, changed requests, unavailable/error/empty states and both closing states. Exact-commit results are generated by release certification and linked from the draft PR; passing automated images does not substitute for human approval.
